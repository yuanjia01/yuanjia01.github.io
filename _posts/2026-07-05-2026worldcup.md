最近好友群里天天都在聊世界杯，但我本身对足球一窍不通，每次群内讨论都根本插不上话，只能默默旁观，偶尔附和一句"这么厉害"，纯粹充当气氛组。

网上各类赛事资讯又十分碎片化，今天刷到这个队出线，明天看到那个教练下课，不成体系。每天问豆包又觉得低效，问完就忘。要是AI能帮我做一份系统总结就好了。

直到我尝试下达一句简单指令：**"帮我查一下 2026 年世界杯的情况"**。

AI就自己上网搜资料、整理内容、开飞书文档、写进去。两分钟不到，一份完整的报告就出来了。

![](/images/img1.png)

看到文档出现在飞书列表的那一刻，我着实感到惊喜：原来实现自动化信息汇总，能这么简单、这么丝滑。

下面就和大家分享一下背后的工具——**OpenCode**，以及一个零基础的人是怎么一步步把它跟飞书打通的。

## 一、先说说我为啥搞这个

毕业不久，财务专业，上次写代码还是在毕业论文的时候，离谱吧。但我对 AI 工具有种说不清的感兴趣——可能是因为总觉得它能帮上忙，但又不知道怎么用。

Claude Code、Codex 这些名字听过，但要么需要魔法上网，要么付费使用成本较高。唯一用过的就是豆包和千问，也只是当高级搜索引擎使。直到刷到了 OpenCode——GitHub 上的一个开源AI智能体（AI Agent)，不用翻墙，直接能在电脑里跑。

![](/images/img2.png)

当时我就想：既然它能操作电脑，那让它帮我写飞书文档，不过分吧？

我工作日用得最多的工具就是飞书文档：调研、周报、整理资料，全在飞书里。但有件事一直让我很烦——从"我想好内容"到"一篇完整的飞书文档摆在那"，中间隔着打开飞书、新建文档、写内容、排版、分段、加标题……一堆零碎操作。

如果能让 AI Agent 直接帮我写到飞书上，那该多省事？

事实证明：确实不过分，但得找对方向。

## 二、先踩了 MCP 的坑

网上搜了一圈，都说通过 **MCP（Model Context Protocol）** 把飞书接给 AI 就行。说实话我也不清楚 MCP 到底是什么，但直接告诉 AI Agent：按这个方式帮我打通飞书。它收到指令后立刻热火朝天开干了。

然后就是连环碰壁：

1. 去飞书开放平台注册应用、填信息、申请权限
2. 拿到 App ID 和 Secret 还不够，还要配权限、配事件、配域名
3. 配完还不行，经历了很多报错
4. 终于跑通了——文档在飞书里根本看不到，它属于"系统应用"，不属于我

很多报错我看都看不懂，排查都不知道怎么排。折腾了一下午，心态炸了。

## 三、方向对了，路就顺了

后面换了个思路，发现了 **lark-cli**——飞书官方的命令行工具。

接飞书其实有两种方式。MCP 是面向开发者的"万能说明书"，什么都能做但第一步走通就很难。CLI 是面向普通用户的，甚至不用知道 API 是什么，两条命令就完事。

说人话就是：MCP 就像一个人想进一栋大楼办事，得先填入职申请、背调、拿工牌、记门禁密码。好不容易进去了，发现要找的部门在另一栋楼。而 CLI 就像门口有个接待员，跟他说"我要去 3 楼会议室"，他直接带你进去。

用 CLI 接入，只要两步：

```
// 1.初始化，自动创建飞书应用
lark-cli init

// 2.扫码授权，绑定到个人账号
lark-cli auth login
```

![](/images/img3.png)

前后五分钟，直接能在飞书里看到。

**以前：** AI 出文字 → 复制 → 打开飞书 → 新建文档 → 粘贴 → 调格式

**现在：** 一句话的事，它直接做好，再发回链接。

## 四、见证时刻

连上飞书后，我试了一下：

"帮我查一下 2026 年世界杯的情况，在飞书生成一篇调研报告"

![](/images/img4.png)

AI Agent 收到指令后：

1. 上网搜索 2026 世界杯最新信息
2. 整理成结构化内容，标出重点
3. 调用 lark-cli 创建新的飞书文档
4. 把格式化好的内容写进去，包括标题层级、表格、重点标注

我在旁边看着它一行一行跑日志，像实习生在埋头干活，我在旁边监工。

经过几轮简单反馈修正后，最终产出的文档长这样：

![](/images/img5.png)

它是怎么做到的？

用大白话解释一下背后的原理。其实就三层：

**第一层：系统提示词 Prompt（指令）**—— 我输入提示词，相当于给 AI 下达的命令。

**第二层：大模型（决策大脑）**—— 大模型读懂我的需求，对照提示词里的规则，自动判断需要启用飞书相关执行工具，输出对应的调用指令。

**第三层：Python 脚本 + 飞书 CLI（实际干活的工具）**—— 飞书 CLI 是官方封装好的命令行工具，类似万能遥控器；配套 Python 脚本持有飞书接口凭证，接收大模型下发的指令，调用 CLI 去创建文档、填充内容、配置权限，最后把文档链接传回给我。

这三层配合起来，效果就是：我下达需求 → 大模型识别意图 → 查阅预设 Prompt 确定操作方案 → 下发指令给 Python 脚本 → 脚本调用飞书 CLI 操作飞书 → 自动生成完整文档并返回链接，全程无需手动操作。

## 五、几点小感受

**1. 技术应该让人省力**

我以前一直觉得 AI 编程工具跟我没关系——我又不写代码，用它们干嘛？但 AI Agent 让我意识到，这些工具的想象力不止于写代码。它们真正的价值是：让一个不懂技术的人，也可以用自然语言去操控复杂系统。我想写个飞书文档，说句话就行。我想做个调研报告，说句话就行。我想整理资料，说句话就行。**技术最好的状态，就是感受不到它的存在。**

**2. 门槛比想象的低**

作为一个财务专业、0 代码基础的小白，现在也能让 AI 替自己干活了。这里面最大的门槛是什么？不是钱，不是技术，而是"我也可以试试"这个念头。没开始前总把困难想得很大，真正上手才发现，工具就在那里，**很多时候阻止我们的不是能力，是那个"万一不行呢"的犹豫。**

**3. AI 是副驾驶，人依然是机长**

一开始我让 AI 走 MCP 接飞书，它热火朝天地干了一下午，结果方向错了，文档属于"系统应用"，我看都看不到。我重新理了思路，告诉它走 CLI，几分钟搞定。

AI 会犯错，会走弯路，会一本正经地胡说八道。它是个很好用的工具，但方向感还是得人来把握。身处 AI 浪潮，很多时候比拼的不再是会操作多少工具，而是两项底层能力：**好奇心和判断力**。前者驱使我们主动尝试多种实现路径；后者则帮我们筛选出正确、可行的方案！
