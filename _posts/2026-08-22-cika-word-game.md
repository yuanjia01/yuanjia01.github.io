作者：圆仔

暑假一到，我妹就抱着平板玩个不停。这次期末考试，她的英语成绩不太理想，妈妈本来就有些发愁，看到她每天沉浸在平板游戏里，就更头疼了。我便想着，有没有什么一举两得的办法，既能让她玩游戏，也能顺便练练英语。于是，我决定试着做一个和英语有关的网页小游戏。

我原本只想做一个简单的中英文配对消消乐，结果一边做、一边改，年级词库、单词本、音标学习和发音功能都慢慢加了进来。我也给这个小游戏取了一个名字——**词咔**。

![图 1｜词咔最新版首页：先学音标，再用两种消消乐巩固](/images/article-content/wordgame06/wordgame06-01-cika-home.png)

## 01 从 9 组配对开始

第一版的目标很简单：先做一个最小可用的版本——不急着把所有功能做全，先让最核心的流程跑起来，再根据真实使用继续增加功能。

在这个 **Vibe Coding** 时代，做这样一个小游戏，不一定要先系统学会编程。AI 可以根据描述生成和修改代码，但前提是我得先把玩法想清楚。需求如果只有一句“做一个好玩的单词游戏”，AI 也很难知道“好玩”究竟长什么样。

所以，我先把规则写得尽量具体：

```text
每一关随机抽取 9 组中英文单词，拆成 18 个泡泡。
连续点击两个泡泡，英文和对应中文配对成功就消失；
配错时给出提示，全部消除后显示通关。
```

为什么是 9 组？因为 18 个泡泡在平板上可以排成 6 列 3 行，一屏就能看完。词太少，没有配对的感觉；词太多，第一眼又容易劝退。9 组不是经过什么严谨研究得出的标准答案，只是我边看页面边试出来的第一版。

第一版能不能交给妹妹试玩，我只看四件事：能否随机生成一局、配对判断是否准确、点错后有没有明显反馈、通关后能不能换一批词。四个环节跑通，游戏才算真正能玩。我把它交给妹妹，观察她会不会主动点开、玩完一关后还愿不愿意继续；她的真实反应，决定后面要不要往下改。

## 02 HTML、CSS 与 JavaScript

看到游戏真的在浏览器里跑起来时，我还是有点惊喜。编程基础不算多的我，居然真的做出了一个可以点击、可以计时、还能通关的网页游戏。

高兴之余，我也开始好奇：AI 到底写了什么？浏览器又是怎么把这些代码变成游戏的？于是我顺着现有代码，把它从文件到运行的过程捋了一遍。

一个网页最核心的三根支柱是 **HTML、CSS 和 JavaScript**。HTML 负责页面里有什么，相当于搭骨架；CSS 决定这些内容长什么样；JavaScript 则负责页面如何响应操作，让按钮能点击、游戏能判断、计时器能运行。

“词咔”的大头同样是这三部分：HTML 放置首页、按钮、棋盘和通关弹窗；CSS 画出森林背景、立体泡泡和消失动画；JavaScript 负责抽词、洗牌、记录点击、判断配对和切换关卡。再加上词库、声音和网页发布，才组成一个可以分享的完整游戏。

| 部分 | 使用的技术 | 在游戏里负责什么 |
|---|---|---|
| 页面结构 | **HTML** | 放置标题、按钮、计时器、泡泡游戏区和通关弹窗 |
| 画面样式 | **CSS** | 控制森林背景、泡泡样式、摇晃和消失动画 |
| 游戏规则 | **JavaScript** | 抽词、洗牌、记录点击、判断配对和切换关卡 |
| 数据内容 | **JavaScript 数据文件** | 保存单词、翻译、难度、年级和 44 个音标 |
| 声音反馈 | **Web Speech API、Web Audio API、音频文件** | 朗读单词和音标，并生成成功、失败和通关音效 |
| 网页发布 | **GitHub Pages** | 把游戏文件发布成任何人都能打开的网址 |

这些部分连在一起，大致是这样的：

```text
词库和音标数据提供内容
    ↓
JavaScript 抽取内容、洗牌并生成一局游戏
    ↓
HTML 和 CSS 把数据变成可以点击的页面
    ↓
朗读、音效和动画反馈点击结果
    ↓
GitHub Pages 把整套文件发布到网上
```

打开网址后，GitHub Pages 会把 HTML、CSS、JavaScript、词库和音频文件发送给浏览器。浏览器读取 HTML 后，会把标题、按钮和棋盘等内容整理成一棵可以操作的页面结构，这叫 **DOM**。JavaScript 再去创建和修改这些页面元素，随机选词、判断配对、计时和播放反馈也都在当前设备的浏览器里完成。

## 03 中文和英文单词如何配对？

搞清楚 HTML、CSS 和 JavaScript 各自负责什么后，我继续顺着 JavaScript 往里看。页面上的泡泡只是外观，真正决定一局能不能玩的，是程序如何记住两次点击，并判断它们是不是同一组。以 `water` 和“水”为例，词库里的一组数据可以理解为：

```js
["water", "水", "lower"]
```

前两个位置分别是英文和中文，第三个位置表示它属于哪个难度档。程序抽中这组数据后，会生成两个泡泡：一个显示 `water`，另一个显示“水”。文字虽然不同，背后却会带上同一个内部编号 `key`。

这个 `key` 相当于两张卡片的配对暗号。玩家看不见，程序却可以用它判断两个泡泡是不是一组。同时还要检查两张卡片的类型不同，否则连续点击同一个英文泡泡，也可能被误判成配对成功。

9 组词拆成 18 个泡泡以后，还要把顺序打乱。这里用了接近 **Fisher-Yates 洗牌算法** 的方法：从数组后面往前走，每次随机挑一个位置交换，让泡泡在每一局里重新排列。

玩家点击泡泡时，程序会统一监听包含 18 个泡泡的整个游戏区域，再判断实际点中了其中哪个泡泡，这种做法叫 **事件委托**。下一关重新生成 18 个泡泡时，原来的点击逻辑仍然可以继续使用，不用再给每个泡泡单独绑定一次。

一次配对背后的流程是：

```text
第一次点击：记住泡泡，并显示选中效果
第二次点击：比较两个泡泡的 key 和类型
配对成功：播放反馈，两个泡泡消失
配对失败：两个泡泡摇晃，然后恢复
成功 9 组：停止计时，弹出通关页面
```

程序还要记住第一次点中了谁、已经消除了几组、这一关什么时候开始。这些看不见的信息统称为**状态**。选中高亮、错误摇晃和配对消失，则把状态变成玩家可以马上看懂的反馈。

## 04 单词如何发出声音？

基础配对跑通后，我想让妹妹点击英文时可以顺便听到发音，选对、选错和通关时也有明显反馈，于是又加入了计时、朗读和音效。看起来只是多了几个小功能，实际试玩时却接连碰到了问题。

首先是计时。程序不能只让数字每秒加一，因为网页短暂卡顿或切到后台时，计时可能越走越偏。现在的做法是在第一次点击时用 `Date.now()` 记下开始时间，之后始终用“当前时间减去开始时间”计算真实用时。离开游戏页时，还要同时停止计时器并清空开始时间。

其次是发音。电脑上可以正常朗读，到了平板上却可能没有声音。原因并不是某一个按钮坏了，而是不同设备对网页音频的规则不一样：电脑浏览器通常可以调用系统自带的英式语音，手机和平板则可能没有对应语音包，还会限制脱离点击动作之后才开始的播放。

现在的处理方式分成了两条路径：

- 电脑端优先使用浏览器提供的英式语音；如果没有可用语音，再切换到英式单词录音。
- 触屏设备直接在点击动作里播放单词录音，避免异步等待后被系统判定为“自动播放”而静音。

连续快速点击时，新声音还要主动停止上一段，否则几个单词会叠在一起。成功、失败和通关提示音则由 **Web Audio API** 临时合成，不需要额外准备“成功.mp3”和“失败.mp3”。

这轮修改让我发现，**同一个网页在电脑上能用，不代表放到平板上就会原样工作**。设备有没有语音包、浏览器何时允许播放、用户的点击是否还在当前操作链里，都会影响最后能不能听到声音。

## 05 能导入自己的单词吗？

配对、计时和发音跑通后，下一个直接影响体验的问题是内容。如果每局总是那几十个词，玩几次就会重复；如果所有难度混在一起，又不一定适合妹妹。于是我先加入了 3—9 年级入口，后来又继续扩充整个词库。

![图 3｜年级选择入口：目前支持 3—9 年级和全部词库](/images/article-content/wordgame06/wordgame06-03-grade-select.png)

目前，内置词库已经扩充为 **3129 个新概念英语 1—4 册词汇**，并按三档组织：第一册作为偏基础词池，第二册作为中等词池，第三、四册作为较难词池。选择某一档时，每关会从主难度抽 5 组，再从另外两档各抽 2 组；选择全部词库时，则按 4 组基础、3 组中等、2 组较难来组合。程序也会尽量避开上一关刚出现过的词。

不过，页面上的“3 年级”并不等于某个版本教材里的“三年级课本词汇”。目前年级按钮更接近难度入口，不同地区、教材和学校进度也不一样。与其假装一套内置词库适合所有孩子，我后来加了一个更实际的功能：**导入自己的单词本**。

它支持三种输入方式：

1. 每行只写一个英文单词或短语，程序先查内置词库，再尝试自动补中文释义。
2. 每行直接写“英文 + 中文”，例如 `banana, 香蕉` 或 `cat 猫`。
3. 导入 JSON 格式的词表，适合从其他工具批量整理数据。

导入时，程序会检查空内容、重复词和无法识别的行，并告诉我成功导入多少、跳过多少。新的单词本会保存在当前浏览器里，回到首页后可以在“内置词库”和“自定义词库”之间切换。

这样一来，妹妹这周作业里刚好错过的词，不必等我重新修改网站代码，整理成几行文本就能变成下一局游戏。

## 06 从音标游戏到学习闭环

最早，“词咔”只给妹妹一个人玩。后来她把链接转给同学，有同学问她：“可不可以再做一个音标消消乐？”我觉得这个想法不错，于是把音标和示例词做成新的配对玩法，找到对应的一组就可以消除。

![图 4｜音标玩法：将音标与示例词、中文提示配对](/images/article-content/wordgame06/wordgame06-04-phonetic-play.png)

音标消消乐做出来后，我又意识到一个问题：如果用户本来就没有学过音标，直接进入消消乐其实更像猜题。要让这个功能真正帮助学习，前面还应该有“先学”的过程，游戏则用来巩固和测验。

所以，最新版首页把“音标学习”放在最前面，整个过程被拆成 7 课：短元音、长元音、双元音、爆破音、摩擦音、破擦音与鼻音、近音与边音，共覆盖 **20 个元音和 24 个辅音**。

![图 5｜音标学习课程页：44 个音标拆成 7 课，并记录完成进度](/images/article-content/wordgame06/wordgame06-05-phonetic-learning.png)

每一课不是只放几张卡片，而是形成一个小闭环：

```text
逐个点击音标，先把本课发音听完
    ↓
完成 5 道听音辨音题，正确率达到 80%
    ↓
进入只包含本课音标的消消乐测验
    ↓
通过后记录本课完成进度
```

在学习卡片里，除了单独听 `/iː/`、`/ɑː/` 这样的音标，还可以点击示例词，按音素逐段播放，再合成完整单词。例如 `see` 会按照 `/s/ → /iː/ → see` 的顺序播放，页面上对应的音标也会跟着高亮。

![图 6｜音标卡片：可以单独听音，也可以按音素分段拼读示例词](/images/article-content/wordgame06/wordgame06-06-phonetic-study-cards.png)

这部分也是目前改得最细的一块。最初，双元音 `/eɪ/` 是把两个单元音音频拼在一起，听起来像先读一个音、停一下、再读另一个音；`pig`、`cake`、`dog` 里的 `/p/`、`/k/`、`/d/` 又因为爆破很短，按整段时长平均切分时容易切到静音。

现在，12 个单元音使用独立的标准音频；双元音和辅音则从真实英式示例词的有效语音区间中播放。41 个示例词分别记录了有效声音的起止位置，先去掉录音前后的静音，再按音素特点划分播放区间。分段之间留出停顿，最后再播放完整单词。它还不等于专业的语音识别或自然拼读课程，但至少解决了“听起来不像在拼读”和“部分爆破音根本听不到”的问题。

## 07 从一个消消乐，到「词咔」

这个项目不是先把 HTML、CSS 和 JavaScript 全部学完，再开始动手，而是先做出第一版，遇到具体问题后，再回头了解对应的技术。一个功能从想法到完成，大致会经历这样的循环：

1. 我先描述页面上应该发生什么，例如“完全没学过音标的人，先学完一课，再进入这一课的消消乐测验”。
2. AI 根据现有项目生成或修改代码。
3. 我在电脑和平板上真的点一遍，看画面、声音和流程是否符合预期。
4. 如果有问题，我描述具体表现，例如“`cake` 的两个 `/k/` 都听不到”、“双元音像两个声音硬拼在一起”，再进入下一轮修改。

游戏逐渐成形后，妈妈和妹妹都夸我居然真的把它做了出来。但我自己心里很清楚：我现在当然还算不上会独立开发网页游戏。很多代码如果完全脱离 AI，我未必能从头写出来。不过和开始时相比，我已经能大致看懂不同技术负责什么，能分辨一个问题更可能出在数据、规则、页面还是设备兼容，也知道怎么把“发音不对”继续追问成可以验证的具体问题。

这大概就是 Vibe Coding 对我最实际的帮助：**它没有让我一夜之间变成程序员，却给了我一个先动手的入口**。碰到不懂的地方再去查，学到的概念也会立刻落在一个真实功能上，不至于看完就忘。

在真正搭建它的过程中，我也第一次站在开发者的角度，重新看那些平时习以为常的功能。平时玩小游戏、使用 App 时，很多设计顺手到几乎不会被注意；自己做了一遍才发现，**“能用”和“好用”之间隔着很长一段路**。发音准不准、平板有没有声音、词库是否合适、没学过音标的人能不能看懂，任何一个看起来很小的问题，都会影响用户还愿不愿意继续用。

这也让我明白，做出“词咔”并不是终点。一个真正好的、对用户有帮助的产品，并不是功能越多越好，而是能持续听见用户的问题，再一处处把卡住他们的地方改掉。这条路还有很长，而我现在只是刚刚走完了第一小段。

目前，“词咔”已经上线，但我也知道它还有不少问题需要继续优化。比如，音标课程进度和自定义单词本还只保存在当前设备的浏览器里，换设备、换浏览器或清除浏览器数据后，记录就不会跟过去。错词回顾、词库校对和平板操作，也还有不少细节需要继续完善。

**试玩地址：** https://yuanjia01.github.io/word-match-game/

如果你身边也有正在背单词、又很爱玩游戏的小朋友，也欢迎把“词咔”转给他试试。哪里不好用、哪个词有问题、还想增加什么玩法，都可以告诉我，我会根据真实反馈继续往下改。
